# ExploreWithMe — Graduation Project

## О проекте

ExploreWithMe — это сервис для поиска и организации совместного участия в событиях. Пользователи могут публиковать мероприятия, просматривать доступные события, подавать заявки на участие и взаимодействовать друг с другом внутри платформы.

Основная идея проекта — предоставить единую платформу, где можно:

* создавать собственные события;
* искать интересные мероприятия по категориям;
* собирать участников;
* управлять заявками на участие;
* получать рекомендации и подборки событий;
* отслеживать популярность мероприятий.

Проект реализован в формате микросервисной архитектуры с разделением ответственности между сервисами. Отдельный сервис статистики собирает информацию о просмотрах событий и обращениях к API, что позволяет анализировать активность пользователей и популярность мероприятий.

Система поддерживает публичное API для неавторизованных пользователей, закрытое API для зарегистрированных пользователей и административное API для модерации контента и управления системой.

## Архитектура проекта

Проект построен по микросервисной архитектуре и состоит из нескольких независимых сервисов.

### Основные модули

#### Core services

* `event-service` — управление событиями, категориями и подборками.
* `request-service` — обработка заявок на участие в событиях.
* `user-service` — управление пользователями.
* `comment-service` — работа с комментариями к событиям.

#### Stats service

* `stats-server` — сбор и предоставление статистики просмотров событий и обращений к API.

#### Infrastructure

* `gateway-server` — единая точка входа в систему. Выполняет маршрутизацию запросов.
* `discovery-server` — сервис регистрации и обнаружения микросервисов (Eureka).
* `config-server` — централизованное хранение конфигурации всех сервисов.

## Взаимодействие сервисов

Взаимодействие между сервисами построено через Spring Cloud инфраструктуру:

1. Все сервисы регистрируются в `discovery-server`.
2. Конфигурации загружаются из `config-server`.
3. Внешние запросы поступают через `gateway-server`.
4. Внутренние сервисы взаимодействуют между собой по HTTP.
5. Сервис `stats-server` используется для сбора статистики просмотров событий.

## Конфигурация сервисов

Конфигурационные файлы расположены в следующих директориях:

### Локальные конфигурации

```text
*/src/main/resources/application.yaml
```

### Централизованные конфигурации

```text
infra/config-server/src/main/resources/config
```

Внутри директории находятся отдельные конфигурации для каждого сервиса:

```text
infra/config-server/src/main/resources/config/core/event-service
infra/config-server/src/main/resources/config/core/request-service
infra/config-server/src/main/resources/config/core/user-service
infra/config-server/src/main/resources/config/core/comment-service
infra/config-server/src/main/resources/config/stat/stats-server
infra/config-server/src/main/resources/config/infra/gateway-server
```

## Внутренний API

Внутреннее взаимодействие сервисов осуществляется по REST API.

### Основные сценарии взаимодействия

* `event-service` обращается к `stats-server` для сохранения и получения статистики просмотров событий.
* `request-service` взаимодействует с `event-service` для проверки состояния события и лимитов участников.
* `comment-service` использует данные пользователей и событий для проверки корректности операций.
* `gateway-server` маршрутизирует запросы к соответствующим сервисам.
